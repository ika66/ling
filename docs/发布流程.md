# 发布流程

从改代码到在 GitHub 上发布一个版本，按下面四步走。

---

## 一、改版本号

`app/build.gradle.kts`：

```kotlin
versionCode = 38      // 每次发版 +1，必须比上一版大，否则无法覆盖安装
versionName = "2.0.2" // 与 Git tag 保持一致（tag 写作 v2.0.2）
```

同时在 `CHANGELOG.md` 顶部加一节，写清「新增 / 变更 / 修复」。

---

## 二、构建 APK

```bash
# Windows
gradlew.bat assembleRelease

# macOS / Linux / Git Bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

安装验证：

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

### 签名（已配置完成）

从 **v2.1.0** 起使用自有 keystore 签名，配置已接入 `app/build.gradle.kts`：

- 密钥文件：`C:/Users/<你>/.ling-signing/ling-release.jks`（仓库外，另有一份备份配置在同目录）
- 参数：`keystore.properties`（仓库根目录，**不入库**）
- 逻辑：`keystore.properties` 存在 → 用正式密钥签 release；不存在 → 回退 debug 签名，
  保证别人 clone 后 `assembleRelease` 仍能跑通

> ⚠️ **keystore 一旦丢失，就永远无法再更新这个应用**（Android 要求升级包签名一致），
> 只能换包名重新发布。请把 `ling-release.jks` 和密码**至少备份两处**（网盘/U盘/密码管理器）。
>
> 因为是私钥，**不要**提交到任何仓库，也不建议放公开网盘。

换电脑或重建时，按下面的方式生成：

```bash
keytool -genkeypair -v -keystore ling-release.jks -keyalg RSA -keysize 2048 \
        -validity 10950 -alias ling
```

然后在仓库根目录建 `keystore.properties`（已在 `.gitignore` 中）：

```properties
storeFile=C:/Users/你/.ling-signing/ling-release.jks
storePassword=你的密码
keyAlias=ling
keyPassword=你的密码
```

> 从 2.0.2 及更早版本升级的用户，签名不同，**必须卸载重装一次**
> （卸载前记得先用应用内「导出备份」，重装后导入）。2.1.0 之后的版本可以正常覆盖升级。

---

## 三、提交并打标签

```bash
git add .
git commit -m "release: v2.0.2"
git tag v2.0.2
git push origin main
git push origin v2.0.2
```

> 只推 `main` 不推 tag 的话，GitHub 上不会出现这个版本标签。

---

## 四、在 GitHub 发布 Release

### 网页操作

1. 打开仓库 → 右侧 **Releases** → **Draft a new release**
2. **Choose a tag** 选 `v2.0.2`（或新建）
3. 标题填 `v2.0.2`，说明从 `CHANGELOG.md` 对应段落复制
4. 把 `app-release.apk` 拖进附件区（**APK 不入库，只放 Release 附件**）
5. 点 **Publish release**

### 命令行（gh）

```bash
gh release create v2.0.2 \
  "app/build/outputs/apk/release/app-release.apk#铃 v2.0.2" \
  --title "v2.0.2" \
  --notes-file <(sed -n '/## \[2.0.2\]/,/## \[2.0.1\]/p' CHANGELOG.md | head -n -1)
```

---

## 附：为什么 APK 不进仓库

- 仓库体积会随每个版本膨胀，克隆越来越慢
- Git 无法有效压缩二进制，历史永久留存
- Release 附件单独托管，下载有版本号与更新说明，更适合分发

`.gitignore` 已经排除 `*.apk`、`*.aab`、`build/`、`local.properties` 与所有 `*.jks` / `*.keystore`。

---

## 附：提交前自查清单

- [ ] `versionCode` 已 +1，`versionName` 与 tag 一致
- [ ] `CHANGELOG.md` 已更新
- [ ] 真机装过一遍，关键路径点过（新增记录 / 详情页 / 拖动排序 / 主题切换 / 返回键）
- [ ] 没有把 `local.properties`、keystore、个人备份 JSON 提交进去
- [ ] `git status` 里没有意外的大文件
